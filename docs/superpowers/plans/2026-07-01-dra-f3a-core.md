# DRA F3a — Scalar Approximation Core Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax. TDD. Branch `dra-f3a` (deps already upgraded: kube 0.98 + k8s-openapi 0.24 / v1_32 / resource.k8s.io/v1alpha3).

**Goal:** Model DRA as synthetic integer extended resources so DRA-requesting pods ride the existing generic solver path. Per node, count unallocated devices matching each DeviceClass; per pod, sum claim demand per DeviceClass. Correctness is deliberately NARROW (bare classes + attribute/driver equality selectors); anything needing full CEL is not counted and is caveated.

**Architecture:** A pure `ksolver/src/dra.rs` operates on k8s-openapi v1alpha3 types: `DraModel::from_raw(slices, classes, claims)` computes `available[(node, class)] -> i64` and per-claim demand. It uses a tiny CEL-subset evaluator that recognizes ONLY device selectors reducing to a single equality over `device.driver` or `device.attributes[...]`; unrecognized selectors mark the class "unevaluable" (devices not counted, pods caveated). No solver change. Collector wiring + live verification are follow-on tasks (this plan is the pure, unit-tested core).

**Tech Stack:** Rust, k8s-openapi 0.24 `resource::v1alpha3`.

## Narrow correctness contract (codex #1–#3 from the design spec)

- **Selector evaluation (limited):** a DeviceClass matches a device iff EVERY class selector matches. A selector matches iff its CEL `expression` parses to a supported equality (`device.driver == "X"`, or `device.attributes["KEY"].string|int|bool|version == <literal>`) that holds for the device. Empty/no selectors ⇒ matches ALL devices. Any selector we cannot parse ⇒ the class is **unevaluable** ⇒ its devices are not counted and DRA pods for it are caveated ("DRA: selector not fully evaluated"), NOT silently treated as feasible.
- **Allocation source of truth = `ResourceClaim.status.allocation`, NOT slices.** A device identity is `(driver, pool, device-name)`. Availability(node, class) = (devices on that node's `nodeName`-scoped slices matching the class) − (those identities appearing in any claim `status.allocation.devices.results`).
- **Node scoping:** only `spec.node_name`-scoped slices are attributed to a node (MVP). `all_nodes`/`node_selector`/per-device selection ⇒ not attributed (documented gap).

### Task 1: Pure `dra.rs` — types + CEL-subset evaluator

**Files:** Create `ksolver/src/dra.rs`; add `pub mod dra;` to `ksolver/src/lib.rs` (or main module list).

**Interfaces:**
```rust
pub struct DraAvailability { pub by_node_class: std::collections::BTreeMap<(String, String), i64>, pub unevaluable_classes: std::collections::BTreeSet<String> }
pub fn compute_availability(slices: &[ResourceSlice], classes: &[DeviceClass], claims: &[ResourceClaim]) -> DraAvailability;
pub fn claim_demand(claim: &ResourceClaim) -> std::collections::BTreeMap<String, i64>; // device_class_name -> count
// internal: enum SelectorMatch { Yes, No, Unevaluable }; fn eval_selector(expr:&str, dev:&BasicDevice) -> SelectorMatch
```

- [ ] **Step 1: Write failing tests** for the CEL-subset evaluator (`eval_selector`): `device.driver == "gpu.nvidia.com"` matches a device whose owning slice driver is that (pass driver in), `device.attributes["model"].string == "A100"` matches when attr present/equal, mismatched value ⇒ No, unsupported expr (`device.attributes["x"].int > 5`) ⇒ Unevaluable, empty selector list ⇒ all match.
- [ ] **Step 2: Implement `eval_selector`** — trim, strip an optional wrapping, split once on `==`, parse LHS as `device.driver` or `device.attributes["KEY"].TYPE`, parse RHS as a quoted string / int / bool literal, compare against the device's driver or attribute value; anything not fitting ⇒ `Unevaluable`.
- [ ] **Step 3: Implement `compute_availability`** — build allocated `(driver,pool,device)` set from claim statuses; for each nodeName-scoped slice, for each device, for each class: if class matches (all selectors Yes; any Unevaluable ⇒ record class unevaluable and skip), and the device identity is not allocated, increment `by_node_class[(node,class)]`.
- [ ] **Step 4: Implement `claim_demand`** — sum `count` (default 1) per `device_class_name` over `spec.devices.requests`.
- [ ] **Step 5: Tests** — a 2-node/2-GPU inventory with one device allocated ⇒ available reflects the subtraction; a class with an unparseable selector ⇒ in `unevaluable_classes`, not counted; claim_demand sums counts.
- [ ] **Step 6: Run — expect PASS**; `cargo test dra` + clippy clean.
- [ ] **Step 7: Commit** — `git commit -am "DRA F3a core: pure availability collapse + limited CEL-subset selector evaluator + tests"`
